Decision before implementation

When the pinned adjacent copy exists but cannot load, may the CLI use a healthy cache copy?

This affects both installation and decode. Fixing only the install check could install a healthy cache copy, then have the worker select the broken adjacent copy again.

OptionConsequence
A. Report the bundled-copy failureClear provenance; requires replacement of that copy. Preserve the current loader's failure behavior.
B. Probe and use the healthy cacheTranscription can recover. Selection must be shared by probe and worker, and native loading stays isolated.

Recommendation: B, with the selected location passed explicitly to the worker. Wrong versions remain ineligible. Cancellation remains cancellation.

Already decided: exact 1.13.8 pin; beside copy preferred when it loads; reuse the existing resolver; one separate fix PR.

What would prove this page wrong

  • A package fixture with the right pin beside a packaged CLI loads in the worker with no cache and no npm call.
  • A wrong pin never loads; an absent copy still follows the cache path.
  • A native abort cannot terminate the parent. Broken adjacent plus healthy cache follows the selected failure policy.
  • Install, availability and worker tests fail when their beside-copy path is removed.
